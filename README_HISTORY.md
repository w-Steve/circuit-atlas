## 使用流程

1. 世界地图可拖动、按钮/双指/键盘缩放；点击背景后滚轮也可缩放，或直接 Ctrl+滚轮。聚合数字表示地点数量，不是比赛轮次；点击聚合标记放大并居中，最大 24 倍仍紧邻的地点提供选择列表。红色描边表示包含 2026 赛历地点。现有模型的地点可进入观赛，其他地点进入真实历史档案。
2. 下方“按年赛历”可选择 1950–2026 赛季；“全部图鉴”可搜索中文、原名、城市及国家。赛历按已举行正赛排序，2026 单独包括计划中的分站。已有模型入口标为“进入现有布局观赛”，不冒充该年的历史布局。档案深链可直接打开和刷新。
3. 直接点击三维看台/草地，拖动圆点连续选点（也支持方向键）；A层级用简短按钮切换。眼高为对应阶梯/草坡表面加1.2米。选点后并列进入视野或相机，两者可互切；视野可转头，固定观察点不自由飞行。
4. 设置80–340km/h并播放经过，暂停/继续保持车位。明确重播才回上游起点，不自动传送循环。A保留首期主直道经过；其他区域的新演示围绕当前选点附近路段。
5. 拿起手机，选择0.5/1/2/3/5/10/20×或直接滑动0.5–30×连续变焦。快门按当前曝光参数生成照片，预览后下载PNG；可在手机里控制赛车播放。
6. 在统一相机界面直接选择1/60、1/125、1/250、1/500、1/1000、1/2000、1/4000秒和固定/理想跟拍。相机取景与导出均模拟快门：慢快门留下实际运动轨迹；理想跟拍保持驾驶舱参考点在原取景位置，背景随之拖动。赛车暂停时速度为零，不产生拖影。

## 物理与摄影约定

- 一单位一米，X东/Y上/Z南；公开GIS中心线闭合后按公布圈长校准，Three的20,000项弧长表驱动车辆，不沿曲线参数假匀速。
- 真实位移=km/h÷3.6×实际秒数。页面隐藏/恢复重置时钟，不补走后台时间。测量取眼点到驾驶舱锚点的三维直线距离，场馆估算误差均标“约”。
- P房取建筑前沿中心，标线距离到中心点，不冒充整栋建筑/整条线最短距离。发车线和计时线独立。
- 实际车体三角形经六面视锥裁切后计算横向占比；不扣除围网的遮挡面积，遮挡本身参与深度测试。
- 手机按全画幅43.27mm对角线保持等效转换到4:3，1×24mm。焦距改变视场角，不改变赛车尺度。
- 所有照片统一冻结快门时的仿真时间、弧长、实际速度、相机矩阵及焦距，以曝光中点多时间采样原场景，在线性sRGB中累积，导出1600×1200PNG。
- 每个曝光样本只临时借用同一车体，逐次try/finally恢复变换和渲染状态；不修改实时simulation.distance/status或车体scale。采样之间实时演示继续，照片始终来自固定拍摄时刻。
- 相同显影管线处理每帧，不是原始传感器HDR曝光。导出样本上限16/24/48；实时GPU预览桌面最多8、触屏最多4个线性光时域样本，不改变快门时间或物理规则。输出像素可能放大设备画布，不预测具体手机画质。

构建前自动生成第三方组件、字体和地理数据许可到`public/licenses`并复制进dist。`node scripts/serve-static.mjs dist /apex/`可在随机本地端口验证项目子路径，终端会输出地址；不依赖Vite或SPA回退。研究脚本的原始缓存未打包，日常构建直接使用已核查的离线赛道包，不需要Python或外部API。

未声称远程上线。共享3D块约895KB（gzip242KB），仍有Vite体积提示；首页按需加载场景，不代表构建失败。手机测试是Chromium设备参数，不冒称真机Safari测试。旧F1-Spectator-delivery.zip为Phase1历史包。
